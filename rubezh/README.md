# AITU Rubezh

Дашборд студента Astana IT University. Название — от «рубежного контроля»: всё крутится вокруг рубежей, которые надо перейти. Собирает в одно место всё, за что тебя
оценивают: дедлайны из Moodle, письма из Outlook, разбор силлабуса — и считает, где ты
стоишь по оценке прямо сейчас.

Открытая замена upahead.com. Работает **локально, на твоём компьютере**: твои куки и
твои данные никуда не уезжают, сервера у этого инструмента нет.

> Соседняя папка [`../tg-digest`](../tg-digest) — выжимка из университетских
> Telegram-групп. Отдельный инструмент, но модель берём из общего `llm.py`.

## Установка

Проще всего — установщик Windows из [Releases](https://github.com/dias-2008/AITU_Rubezh/releases)
или `install.sh` на macOS, см. [корневой README](../README.md). Из исходников:

```
pip install -r requirements.txt
python -m playwright install chromium
python rubezh.py setup
```

`setup` — мастер первого запуска. Он открывается страницей в браузере и по шагам
делает всё, что описано ниже: входы, ярлык, кнопку «Войти», уведомления, первую
сборку. Каждый шаг — кнопка; сделанное отмечено галочкой, так что открывать мастер
можно сколько угодно. Страницу отдаёт локальный сервер только этому компьютеру и
по случайному адресу; закрыл вкладку — он выходит сам. Без браузера (по SSH) —
`python rubezh.py setup --cli`: те же шаги вопросами в консоли. Дальше в этом README — что каждый шаг значит
и как сделать то же самое руками.

## Вход (один раз)

```
python rubezh.py login lms        # откроется окно Moodle, логинишься руками
python rubezh.py login du         # портал: имя, группа, расписание
python rubezh.py login outlook    # почта — по желанию, нужна Ollama
```

Окно закроется само, когда вход подтвердится. Дальше инструмент работает без тебя:
профиль браузера с куками лежит в `.sessions/` и переживает перезапуски.

На экране Microsoft «Stay signed in?» жми **Yes**.

**Настрой MFA, когда Microsoft попросит.** Экран «Let's keep your account secure» нельзя
пройти автоматически — он для того и сделан. Пока он всплывает, инструмент не сможет
переподнимать сессию сам и будет дёргать тебя каждые пару недель. Один раз настроил —
дальше он входит без тебя.

Проверить, живы ли сессии:

```
python rubezh.py status
```

## Почему через браузер, а не через API

Так вышло не от хорошей жизни, и это стоит знать, если будешь дорабатывать.

У Moodle AITU **веб-сервисы включены** (`enablewebservices: 1`), но оба публичных входа
закрыты на nginx:

```
403  /login/token.php               токен получить негде
403  /webservice/rest/server.php    REST API недоступен
200  /lib/ajax/service.php          а вот этим сайт пользуется сам
```

`/lib/ajax/service.php` — эндпоинт, через который страницы Moodle дёргают свои же внешние
функции. С живой сессией нам доступно ровно то, что видит браузер: курсы, дедлайны, оценки.
Мы не ломаем ничего и не обходим ограничения — читаем свои данные своей же сессией.

Проверено на живой сессии 30.08.2026 — открыто **2 функции из 9**:

```
[OK]      core_calendar_get_action_events_by_timesort     дедлайны — главное, что нужно
[OK]      core_calendar_get_calendar_monthly_view         календарь на месяц
[ЗАКРЫТО] core_enrol_get_users_courses                    список курсов
[ЗАКРЫТО] core_course_get_contents                        содержимое курса
[ЗАКРЫТО] mod_assign_get_assignments                      задания
[ЗАКРЫТО] gradereport_user_get_grade_items                оценки и веса
[ЗАКРЫТО] gradereport_overview_get_course_grades          итоги по курсам
[ЗАКРЫТО] core_webservice_get_site_info                   инфо о сайте
[ЗАКРЫТО] core_message_get_messages                       сообщения (мессенджер выключен)
```

Повезло: **дедлайны отдаются по API**, а это самое важное. Оценки и курсы закрыты, их
добираем чтением обычных страниц через ту же сессию — проверено, открываются:

```
/my/courses.php                      список курсов
/grade/report/overview/index.php     оценки по всем курсам
/calendar/export.php                 постоянная ссылка на календарь
```

Свой список проверить: `python rubezh.py probe`.

### Осторожно: перед Moodle стоит WAF, он смотрит на User-Agent

Запрос с дефолтным `python-requests/...` получает **403 Access Blocked** — это не Moodle,
а фильтр перед ним. С обычным браузерным User-Agent та же ссылка отдаёт 200.

```
без User-Agent          HTTP 403
браузерный User-Agent   HTTP 200   BEGIN:VCALENDAR
UA календаря Apple      HTTP 200   BEGIN:VCALENDAR
```

Последняя строка важна: значит, **iPhone может подписаться на ссылку напрямую**.
Любой свой запрос к lms.astanait.edu.kz подписывай нормальным User-Agent.

## Календарь: постоянная ссылка

```
python rubezh.py ics
```

Достаёт ICS-адрес и кладёт в `secrets.json`. Внутри `authtoken`, привязанный к пользователю,
а не к сессии — ссылка живёт и после того, как кука протухнет.

**Это доступ к твоему календарю без пароля.** `secrets.json` в `.gitignore`, но проверь
сам перед первым `git push`.

У Microsoft причина другая: регистрация стороннего приложения может упереться в согласие
админа тенанта (AITU — управляемый тенант `158f15f3-...`). Сессия браузера обходит вопрос
целиком: ничего регистрировать не надо.

## Как в этом универе считается оценка

Из силлабуса (шаблон общеуниверситетский, меняется только состав заданий):

```
Итог = 0,3 x Аттестация1 + 0,3 x Аттестация2 + 0,4 x Финал
```

Каждая аттестация из 100: задания и квиз дают 60, Mid Term / End Term — 40.

**Два способа завалить курс, не связанные с баллами.** Инструмент следит за обоими,
потому что по одним процентам их не видно:

- посещаемость ниже **70%** — не допустят до экзамена; пропуск 30% без причины = «не аттестован»;
- меньше **25%** за любую из двух аттестаций — автоматический незачёт.

Шкала: 95+ = 4.0, 90-94 = 3.67, 85-89 = 3.33, 80-84 = 3.0, 75-79 = 2.67, 70-74 = 2.33,
65-69 = 2.0, 60-64 = 1.67, 55-59 = D+, 50-54 = D, 30-49 = FX, ниже = F.

## Безопасность

`.sessions/` — это полный доступ к твоим университетским аккаунтам. Папка в `.gitignore`,
но проверь сам перед первым `git push`. Если утечёт: смени пароль и выйди из всех сессий

Инструмент ничего не отправляет наружу, кроме текста, который ты сам скармливаешь модели

## Дашборд

Самый быстрый способ — ярлык на рабочем столе:

```
python rubezh.py shortcut
```

Кладёт «AITU Rubezh» на рабочий стол, а на Windows ещё и в меню «Пуск» (там его можно
закрепить правым кликом). По двойному клику дашборд пересобирается свежими
данными и открывается в браузере. Окно консоли свёрнуто и нужно только на случай ошибки.
На macOS это файл `AITU Rubezh.command` — открывается в Terminal. Установщик Windows
кладёт ярлык сам.

Без ярлыка то же самое делает:

```
python rubezh.py open
```

Просто открыть уже собранный файл, ничего не пересобирая, можно и двойным кликом по
`build/dashboard.html` — он самодостаточный, но данные в нём от последней сборки.

### Разделы — отдельные страницы

Сборка кладёт рядом шесть файлов, по одному на раздел:

```
build/dashboard.html   Главная — всё важное на один экран
build/tasks.html       Задания — сроки, статус, тип, балл
build/grades.html      Оценки — рубежи, экзамен, допуск
build/schedule.html    Расписание — сетка дня по часам
build/dates.html       Даты — рубежи и сессия триместра
build/syllabus.html    Силлабус — что вытащили из файлов курса
```

Раньше это была одна длинная страница с якорями, и «Оценки» означало «промотай вниз».
Разметка при этом осталась одна на всех: секции помечены `data-page`, лишние прячутся
при загрузке. Так разделы не разъезжаются между собой при правках, а данные собираются
**один раз на все страницы** — иначе шесть файлов означали бы шесть обходов Moodle.

Главная намеренно осталась `dashboard.html`: на это имя смотрят ярлык на рабочем столе,
обработчик `rubezh://` и открытая вкладка, которая сама перечитывает файл после входа.


```
python rubezh.py build     собрать build/dashboard.html
python rubezh.py serve     то же плюс раздача, чтобы открыть с телефона
```

`build` делает **один самодостаточный HTML-файл**: данные вшиты внутрь, открывается
двойным кликом с диска. Хостить ничего не надо и негде — это принципиально, инструмент
локальный.

`serve` поднимает обычный `http.server` из стандартной библиотеки — зависимостей нет.
**По умолчанию только на `127.0.0.1`**: снаружи не видно.

Чтобы открыть с телефона, нужен явный флаг:

```
python rubezh.py serve --lan
```

Тогда сервер слушает сеть, но отдаёт страницу **только по одноразовому адресу** вида
`http://10.0.0.5:8000/nR7xK2pQeF/dashboard.html`. Токен новый на каждый запуск.

Так сделано не для красоты. На дашборде твоё имя, оценки, посещаемость и список того,
что ты заваливаешь. Раздача на `0.0.0.0` без адреса-секрета означает, что любой в
университетском Wi-Fi, кто просканирует порт 8000, всё это прочитает. Без флага и
без токена — не прочитает.

### Телефон по QR-коду

Проще — кнопка **«Телефон»** в шапке дашборда (или `python rubezh.py phone`).
Компьютер становится сервером, а в браузере открывается страница с QR-кодом:
навёл камеру — на телефоне твой дашборд со всеми страницами.

```
python rubezh.py phone
```

Связь идёт через **быстрый туннель Cloudflare** (`cloudflared`, без аккаунта):
работает с мобильного интернета и в университетском Wi-Fi, где устройства обычно
не видят друг друга и `serve --lan` не помогает. `cloudflared` уже лежит в установщике
рядом с `rubezh.exe` (лицензия Apache-2.0 — `cloudflared-LICENSE.txt` там же);
`install.bat` и `install.sh` скачивают его заранее в `bin/`. Если его нет ни там, ни в
системе — скачается при первом нажатии (около 55 МБ).
Не поднялся туннель — QR-код будет на адрес в локальной сети.

- На телефоне есть кнопка **«Обновить»**: компьютер пересобирает данные, страница
  перезагружается сама. Войти в Moodle или портал с телефона нельзя — окно входа
  открывается на компьютере.
- Раздача работает, пока не нажмёшь **«Остановить раздачу»** или не выключишь
  компьютер. Повторное нажатие «Телефон» откроет ту же страницу, а не вторую раздачу.
- Адрес туннеля новый при каждом запуске — после перезагрузки сканируй заново.
  Правки расписания и тема на телефоне хранятся в его браузере по этому адресу,
  поэтому с новым адресом начинаются заново.

**Чем за это платишь.** В режиме туннеля страница идёт через серверы Cloudflare —
это единственное место, где данные дашборда покидают твой компьютер. Адрес закрыт
секретом, как и у `serve --lan`, и умирает вместе с раздачей. Страница с QR-кодом и
кнопкой «Стоп» — под другим секретом и отвечает только этому компьютеру: кто увидел
ссылку телефона, раздачу не выключит.

Что на экране:

- **плитки** — сдано, среднее по РК, ближайший рубеж, курсы под угрозой;
- **ключевые даты** — из настоящего академического календаря;
- **нагрузка** — месяц, плотность дедлайнов по дням;
- **допуск к экзаменам** — три барьера AITU полосами с засечкой на пороге;
- **задания** — вкладки просрочено / неделя / месяц / экзамены / сдано; название
  задания — ссылка на его страницу в Moodle, открывается в новой вкладке;
- **расписание** — на главной сегодняшний день, на странице «Расписание» любой день
  или вся неделя; онлайн-пары отмечены пунктиром;
- **курсы** — РК1, РК2, экзамен, посещаемость и главное: **сколько ещё нужно набрать**.

Тёмная тема идёт за системной, кнопка «Тема» в углу переключает вручную.

### Кнопка «Войти» прямо на дашборде

Сессии живут примерно сутки, и заходить приходится руками (MFA настроить не вышло,
см. ниже). Чтобы не лезть каждый раз в консоль:

```
python rubezh.py register
```

Регистрирует схему `rubezh://` для твоей учётной записи — права администратора не
нужны. Установщик Windows делает это сам; на macOS команда собирает крошечное
приложение `~/Applications/AITU Rubezh.app` на AppleScript — только приложение может
принимать ссылки своей схемы. После этого, если сессия истекла, дашборд показывает жёлтую полосу с кнопкой
**Войти**: клик открывает окно входа, а когда войдёшь — страница сама перечитает
свежую сборку. Новую вкладку не открываем, иначе на каждый вход копилось бы по одной.

Окно появляется не сразу: под кнопкой запускается Python, Playwright и холодный
Chromium — секунд двадцать. Кнопка на это время так и пишет, «Открываю окно входа…»,
а повторные клики отбрасываются: два процесса в одном профиле Chromium только
мешают друг другу.

Убрать: `python rubezh.py unregister` (снимает и задачу планировщика).

Дашборд лежит на диске и сам ничего запустить не может — поэтому ссылка своей схемы,
которую Windows отдаёт нашему же скрипту. В запуск попадает **только имя сервиса из
известного списка**: ссылку такого вида может подсунуть кто угодно, так что всё
остальное отбрасывается (`rubezh://login/../../etc`, чужие схемы, лишние сегменты).
Под кнопкой на всякий случай написана и обычная команда.

### Расписание: из файла, с правками в браузере

Портал так и не отдал расписание группы по API, а в мобильном приложении оно есть.
Поэтому недельная сетка снята со скриншотов и лежит в `schedule.json`: `day` 1–6
(Пн–Сб), пустая аудитория означает онлайн. Как только портал начнёт отвечать, его
данные будут в приоритете, файл — запасной вариант. Сам файл в репозиторий не идёт;
готовый для группы лежит в `groups/<группа>/` (вместе с `syllabus.json`), мастер
`setup` предлагает его положить, а установщик Windows — галочкой.

На странице «Расписание» кнопка **Изменить** открывает режим правки: поменять время,
аудиторию, преподавателя, добавить или удалить пару. Дашборд — файл на диске, писать
в `schedule.json` из него нечем, поэтому правки хранятся в localStorage этого браузера
поверх файла и переживают пересборку. Обновился сам файл — правки сбрасываются, и
об этом написано на странице. **Сбросить правки** возвращает к файлу.

### Силлабус: вынуть работы и веса из файла

```
python rubezh.py syllabus "Syllabus Calc1.pdf" --course "Calculus 1"
```

Читает PDF, DOCX, TXT и вытаскивает список работ: название, вес в процентах, неделю или
дату. Всё это написано в силлабусе задолго до того, как преподаватель заведёт задание в
Moodle, — значит, план курса можно видеть заранее, а не ждать появления дедлайна.

**Разбирает та же локальная модель, что и почту**, и по тому же правилу: backend зашит
в коде, а не берётся из `config.json`, где однажды может оказаться `auto` — и учебные
файлы уедут в облако. Ollama поднимается только на время разбора.

**Модель здесь переводчик, а не источник правды.** Её ответ проверяется построчно:
дата — регулярным выражением, вес — числом от 0 до 100, всё неразобранное
выбрасывается. Результат лежит в `syllabus.json` и показывается на странице
«Силлабус» **отдельно от заданий Moodle**, с пометкой, из какого файла взято: это план
курса, а не выставленный дедлайн, и путать их нельзя.

**Сканы не читаются.** Часть официальных PDF у AITU — картинки, текста в них нет.
В этом случае честно говорим об этом, а не отдаём пустой список.

#### Прочитанные вручную

Осенью 2026 модель не справилась: четыре силлабуса из шести оказались сканами, а
по пятому она вернула все веса пустыми. План курса с неверными весами хуже, чем без
весов, поэтому в `syllabus.json` есть второй сорт записей — `"verified": "hand"`:
прочитанные человеком по страницам PDF. У такой записи есть всё, чего модель не
достаёт: код курса и кредиты, преподаватели с почтой и офис-часами, баллы по каждой
аттестации (в сумме всегда 100), план по неделям с подтемами, чтением и заданиями
на практику, правила курса. Модель такую запись **не перезапишет**: команда
`syllabus` откажется, пока запись не удалить руками.

Страница «Силлабус» из этого собирает: **ближайшее по всем курсам** начиная с
текущей недели и карточку каждого курса. Выбери предмет во вкладках — и сверху
появится **«К следующему занятию»**: темы, что прочитать и что будет на практике
на этой и на следующей неделе. Преподаватели просят приходить подготовленными по
силлабусу — вот это оно и есть, без листания PDF. План по неделям при этом
раскрывается целиком, с подтемами. Сроки в силлабусе — номера недель; даты
им даёт академический календарь: неделя 1 — первый день теоретического обучения,
и РК1 (05–10.10) в самом деле пятая неделя, РК2 (09–14.11) — десятая. Если
midterm/endterm без недели, показывается окно РК из календаря с пометкой `*`.

### Страницы курсов: то, чего нет в календаре

Календарь Moodle отдаёт только активности со сроком. А «Practice Session 2
пройдёт в формате устного семинара, подготовьте темы…» преподаватель пишет
**текстом в блоке недели** — без срока, без активности. Так и вышло: всё, что
было на дашборде, сдано, а к семинару никто не готовился, потому что дашборд о
нём не знал.

Поэтому [sections.py](sections.py) читает саму страницу курса
`/course/view.php?id=…` — по той же куке, что и журнал, без браузера — и
разбирает секции: «Week N (dd.mm–dd.mm)», плашку **Current week**, тексты
преподавателя, файлы, задания и тесты с их датами и ограничениями
(«Not available unless…») и отметкой Moodle о выполнении — «Mark as done» /
«Done» / «To do», если преподаватель включил отслеживание.

Текст лежит не только в блоке недели. «Practice Session 3 — устный опрос,
что подготовить: …» преподаватель пишет в **описании задания**, а «прочитайте
до занятия» — на **странице** (`page`); со страницы курса от них видно одно
название. Поэтому у заданий, страниц, тестов и форумов текущей и следующей
недели дочитывается их собственная страница, и этот текст показывается под
активностью.

Из него же берётся срок, которого в календаре нет — или есть, но не тот:
у социологии Moodle пишет «до субботы», а опрос — на практике во вторник.
Если текст говорит «before class», «prepare», «к практике», в «Заданиях»
появляется строка **«К занятию»** со сроком — ближайшей парой этого курса по
расписанию (практикой, если речь о практике или семинаре). Курс с парой
сводится по коду: буквы кода — инициалы английского названия (`DMCS`, `ICT`,
`IP`) либо его начало (`SOC`, `PSY`). Не сошлось — строки нет, текст всё равно
виден в карточке недели.

Куда это попадает:

- карточка **«Сделать в Moodle»** на главной и на «Заданиях» — все тесты,
  задания, папки с практиками и прочее из всех недель всех курсов, со статусом
  «сделано / сделать / не сделано»; в «Заданиях» выше только то, у чего есть
  срок в календаре, а тест без даты закрытия или папка «Practice classes 1-3»
  живут только здесь. Где отслеживания нет — так и написано: «нет отметки»;
- карточка **«В курсах Moodle на этой неделе»** на главной и на «Заданиях» —
  текущая секция каждого курса;
- в силлабусе при выборе предмета — блок **«В Moodle сейчас»** рядом с
  «к следующему занятию»;
- `watch` помнит каждый блок по его id и пишет в Telegram
  `📝 Новое в курсе …` и `✏️ Изменилось в курсе …` — именно то уведомление,
  которого не хватало.

```
python rubezh.py sections          текущая неделя каждого курса
python rubezh.py sections --all    все секции
```

Парсер свой, на `html.parser`, под вёрстку Moodle 4/5 (у AITU — 5.x, тема
classic). Если страница поменяется, `sections` покажет пустые секции — это
сигнал править парсер, а не признак того, что в курсах пусто.

### Почта: разбирает локальная модель, наружу ничего не уходит

Университетские письма читаются и разбираются **на этом же компьютере** — `ollama`,
модель `gemma4:e4b`. Backend зашит в коде [outlook.py](outlook.py), а не берётся из
конфига: строка в config.json может однажды оказаться `auto`, и переписка уедет в облако.
Так это невозможно в принципе.

Читаются **только письма от университета**. GitHub, рассылки, личное — отсеиваются
фильтром **до** модели, а не после.

Модель запускается, только когда появилось новое письмо. `gemma4:e4b` весит почти
десять гигабайт, и гонять её каждый час впустую — ровно та трата ресурсов, от которой
мы ушли, перестав запускать Chromium.

Найденное попадает в Telegram (`📧 Из почты: ...`) и на дашборд отдельной карточкой.

**Про побочный эффект.** Открытие письма в Outlook помечает его прочитанным в настоящем
ящике. Поэтому по умолчанию берём только то, что и так видно в списке, и ничего не
открываем: иначе непрочитанное письмо, которое ты ещё не видел, тихо стало бы прочитанным
и могло потеряться. Полные тексты — по явному `full=True` в `outlook.fetch()`, зная это.

### Живые данные и демо

По умолчанию дашборд собирается из **настоящих** данных: Moodle, портал, академический
календарь. Пока курсов нет, он честно пустой и объясняет, чего именно не хватает.
Выдумывать правдоподобные баллы — плохая идея: по ним начинаешь принимать решения.

Посмотреть, как всё выглядит с данными, можно на демо:

```
python rubezh.py build --demo
```

Осенний триместр CS-2606, конец октября: РК1 закрыт, РК2 идёт. **Баллы вымышленные,
даты и формула настоящие.**

### Чего пока нет и почему

**Оценки и посещаемость — со страницы, не по API.** Функции журнала (`gradereport_*`)
на сервере AITU закрыты для ajax, это видно в `python rubezh.py probe`. Зато страница
отчёта студенту открыта и отдаётся по той же куке: `/grade/report/user/index.php?id=`.
Её и читает [journal.py](journal.py) — обычным HTTP, без браузера.

Оттуда берутся ровно две вещи: **Register Midterm / Endterm / Final** — это и есть РК1,
РК2 и экзамен из формулы университета, и **Attendance** — посещаемость, Moodle держит её
как оценку 0-100, то есть уже в процентах. Отдельные задания внутрь аттестаций не
складываем: преподаватель уже сложил их в register-строку, и второй раз считать то же
самое значило бы удвоить максимум.

Невыставленное приходит как `None`, а не ноль, и на карточке пишется «ещё нет». Ноль в
этих местах читается как двойка: «среднее РК 0» — как будто всё завалено, «посещаемость
0%» — как будто не допустят, хотя занятий ещё не было.

**Аттестация у дедлайна — вычисляется по дате.** Раз журнал закрыт, к какой аттестации
относится задание, приходится выводить из академического календаря: всё до конца РК1 —
первая, до конца РК2 — вторая, дальше экзамен. Это единственная догадка в системе, и она
уступит место фактам, как только журнал откроется.

### Почему буква оценки не «сейчас»

Считать букву по набранному сейчас арифметически честно, но в середине триместра
бессмысленно: несданное идёт нулём, и отличник видит FX. Поэтому на карточке —
**потолок** («если сдать всё оставшееся») и статус словом: идёт ровно / нужно
поднажать / под угрозой.

## Уведомления в Telegram

Инструмент сам ничего не делает, пока его не запустят. `watch` — это то, что
превращает его из «зайти посмотреть» в «мне напишут».

Настройка один раз:

```
напиши любое сообщение своему боту в Telegram   (тому же, что у tg-digest)
python rubezh.py telegram                        запомнит, кому слать
python rubezh.py watch --dry                     посмотреть, что бы ушло
python rubezh.py watch                           отправить
```

Токен бота лежит в `.env` рядом (`BOT_TOKEN=...`) — его спрашивает мастер `setup`.
Если рядом настроен tg-digest, возьмётся его `../tg-digest/.env`: второго бота
заводить не надо.

### Фоновая работа раз в час

Задача заводится одной командой — руками в планировщик лезть не надо:

```
python rubezh.py schedule           включить проверку раз в час
python rubezh.py schedule --status  посмотреть, когда запускалась и с каким итогом
python rubezh.py schedule --off     выключить
```

Запустить прямо сейчас, не дожидаясь часа: `schtasks /Run /TN "AITU Rubezh"`

На macOS та же команда ставит агент launchd `~/Library/LaunchAgents/kz.aitu.rubezh.watch.plist`,
лог — `launchd.log` рядом с `rubezh.py`. Как именно всё это делается на каждой
системе — в [desktop.py](desktop.py).

На Windows запускается **pythonw.exe** (из установщика — `rubezhw.exe`), а не
python.exe — иначе каждый час мигало бы окно консоли.
Обратная сторона: консоли нет вообще, `sys.stdout` равен `None`, и обычный `print` там
падает — это учтено. Всё пишется в `watch.log`, туда же уходят ошибки, которые иначе
было бы не увидеть.

`Logon Mode: Interactive only` — задача работает, когда ты в системе. Так осознанно:
иначе Windows потребует сохранить пароль от учётной записи.

### Сколько это стоит

Замерено, а не прикинуто:

| | время | пик Chromium |
|---|---|---|
| первый прогон, ключей нет | 16,4 с | ~355 МБ |
| дальше, по HTTP | **3–4 с** | **0 МБ** |

Между прогонами — ровно ноль: процесса нет. Поэтому это задача планировщика, а не демон:
постоянно висящий процесс занимал бы память круглые сутки ради работы раз в час.

Секрет в [fast.py](fast.py): браузер нужен только чтобы **добыть ключи** — куку Moodle
с sesskey и JWT портала. Ключи лежат в `secrets.json`, и пока живы, проверка идёт
обычными HTTP-запросами. Протухли — браузер поднимается, обновляет их и снова уходит
на быстрый путь.

Ключи снимаются в один момент с сессией — везде, где мы видим живую страницу: ручной
вход, молчаливое переподнятие, `status`, `watch`. Иначе получается так: человек вошёл
руками, а дашборд собрался по вчерашним ключам и снова написал «войди».

Отключение картинок и шрифтов, кстати, **не дало ничего** (358 против 367 МБ): вся цена —
это сам старт Chromium, а не то, что он грузит. Поэтому решение было не «ужать браузер»,
а «не запускать его».

О чём напишет:

- появился курс в Moodle — то самое, чего ждём после 07.09;
- новый дедлайн, **перенос** существующего, снятый дедлайн;
- появилось или изменилось расписание группы на портале;
- открылся транскрипт — значит, поехали оценки;
- **сессия протухла и надо зайти руками** — и, пока она лежит, напоминание раз в сутки.
  Одно сообщение в момент падения легко пропустить, а дальше проверка молчит — и это
  молчание читается как «ничего нового», хотя на самом деле это «я ничего не вижу».

Молчание означает «ничего не изменилось». Состояние прошлого запуска лежит в
`state.json`, поэтому одно и то же не присылается дважды.

**Сравниваем с последним удачным чтением, а не с прошлым снимком.** Разница неочевидная,
но именно она однажды съела уведомление. Пока сессия лежала, снимки приходили пустыми;
когда она поднялась, сравнивать новое было не с чем — в прошлом снимке курсы просто не
собраны, — и сравнение честно пропускалось, чтобы не сыпать «все курсы пропали». В итоге
шесть курсов и первое задание тихо записались в состояние как известные, и человек о них
не узнал: ни строчки в Telegram. Теперь по каждому ключу помнится последнее удачное
чтение (`known` в `state.json`), и простой сессии больше не съедает новости.

### Почему это важнее, чем кажется

MFA у Microsoft настроить не вышло — админ тенанта, судя по всему, не разрешает
самостоятельную регистрацию второго фактора. Значит, сессии будут протухать, и
переподнять их молча инструмент не сможет. Единственный рабочий путь — заходить руками,
когда потребуется. `watch` для того и нужен: он замечает протухшую сессию и пишет об этом,
вместо того чтобы тихо перестать работать.

Отдельно предусмотрено: **если источник лежит, его пустые данные не считаются изменением.**
Иначе каждая протухшая кука присылала бы «все курсы пропали». Проверено тестом.
