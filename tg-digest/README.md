# tg-digest

Читает твои университетские Telegram-группы, выкидывает флуд и присылает в личку боту
короткий дайджест: дедлайны, задания, изменения расписания, объявления — со ссылками
на исходные сообщения.

Работает от твоего аккаунта (Telethon), поэтому видит все группы, где ты состоишь.
Админом быть не нужно.

> Отдельная папка: второй инструмент рядом с [rubezh](../rubezh). Общие у них `llm.py`
> (модель) и `desktop.py` (планировщик), и бот один на двоих.

## Установка

```
cd tg-digest
pip install -r requirements.txt
python setup.py
```

Из установщика Windows — галочка «tg-digest» при установке и ярлык «Настройка
tg-digest» в меню Пуск (то же самое: `digest.exe setup`).

## Настройка (один раз): `python setup.py`

Мастер идёт по четырём шагам, каждый — Enter или `s`, чтобы пропустить. Сделанное он
видит и второй раз не спрашивает.

**1. Ключи Telegram и токен бота.** Дайджест читает группы от твоего аккаунта, для
этого Telegram выдаёт ключи приложения: https://my.telegram.org → API development
tools → создай приложение (название любое) → `api_id` и `api_hash`. Бот для доставки —
@BotFather → `/newbot` → токен. Если рядом настроен rubezh, токен возьмётся из его `.env`.
**Открой своего бота и нажми Start** — иначе он не сможет тебе писать.
Всё ложится в `.env` (образец — `.env.example`).

**2. Модель.** Мастер покажет, что доступно на твоей машине, и спросит `backend`.
Подписка ни на что не обязательна, см. раздел «Чем суммаризировать».

**3. Вход в Telegram и выбор групп.** Первый раз спросит номер телефона, код из
Telegram и пароль 2FA (если включён); сессия сохранится в
`profiles/default/telegram.session`. Потом покажет группы списком с номерами —
введи нужные через запятую (`2, 5-7`).

**Группы-форумы (с темами).** Если у группы есть темы, в списке будет и сама группа,
и каждая тема отдельно, с отступом:

```
     12. AITU Школа КБ
     13.   AITU Школа КБ / 1-курс бакалавры
     14.   AITU Школа КБ / Promotions
```

Бери **темы**, а не группу целиком: иначе объявления для 3 курса и магистрантов будут
идти вперемешку с твоими. У каждой темы свой указатель прочитанного, ссылки в дайджесте
тоже ведут внутрь темы.

**4. Раз в час.** Задача в планировщике (Windows: schtasks без окна, macOS: launchd) —
подробнее ниже.

Без мастера то же самое руками: скопируй `.env.example` в `.env` и заполни,
`python digest.py chats` покажет группы и готовые строки для поля `chats` в
`profiles/default/config.json`.

## Запуск

```
python digest.py run --fake --dry   # вообще без вызова модели: проверить сбор и фильтр
python digest.py run --dry          # настоящая выжимка, но в консоль, без отправки
python digest.py run                # отправит дайджест в бота
```

`--fake` прогоняет весь конвейер (чтение, фильтр, ссылки, формат) и **ни разу не дёргает
модель**. Отлаживай на нём — квота не тратится.

Каждый реальный вызов пишется в `usage.log`, так что всегда видно, куда ушли запросы:

```
2026-08-29 23:50  claude-cli sonnet  ~320 симв. на входе
2026-08-29 23:52  gemini gemini-2.5-flash  вход 4210 / выход 380 токенов
```

Скрипт помнит в `state.json`, до какого сообщения дошёл в каждом чате, поэтому каждый
следующий запуск обрабатывает только новое.

## Несколько человек на одной машине

Каждому человеку — свой профиль. Общими остаются только код и `.env` в корне
(ключи Telegram-приложения, токен бота, ключ Gemini). Различаются:

```
profiles/
  default/            профиль по умолчанию, используется без --profile
    telegram.session  вход в Telegram — ПОЛНЫЙ доступ к аккаунту
    config.json       свои чаты и темы
    state.json        свой указатель прочитанного
    usage.log         свой чек расходов
    digest.log        свой лог прогонов
  aidana/             второй человек
    ...
```

Подключение нового человека — **вход делает он сам**, код приходит на его телефон:

```
python digest.py chats --profile aidana    # телефон, код, при необходимости 2FA
```

Дальше он выбирает свои чаты в `profiles/aidana/config.json`, один раз нажимает Start
у бота — и можно запускать:

```
python digest.py run --profile aidana --fake --dry   # бесплатная проверка
python digest.py run --profile aidana
```

Отдельная задача в планировщике для него: `python setup.py aidana`, четвёртый шаг.

Дайджест уходит в личку тому, чья сессия используется: адресат берётся из самого
аккаунта, поэтому один бот спокойно обслуживает несколько человек и переписки
не смешиваются.

**Профиль без входа не запустится молча.** Под планировщиком `run` не станет ждать ввод
телефона, а скажет, что профиль не авторизован и вход должен сделать владелец аккаунта.

## Автоматически по расписанию

Это четвёртый шаг мастера `setup.py`; отдельно — та же команда для нужного профиля:

```
python setup.py             # профиль default
python setup.py aidana      # второй человек: своя задача «TG Digest (aidana)»
```

На Windows задача «TG Digest» в планировщике запускает `pythonw.exe digest.py run`
(из установщика — `digestw.exe`) раз в час, **без окна терминала**: у процесса
без консоли `sys.stdout` пустой, поэтому `digest.py` сам пишет прогон в
`profiles/<профиль>/digest.log`. На macOS — агент launchd
`~/Library/LaunchAgents/kz.aitu.rubezh.digest.plist`. Как именно — в
[../rubezh/desktop.py](../rubezh/desktop.py), он общий на оба инструмента.

Проверить или снять руками: `schtasks /query /tn "TG Digest"`,
`schtasks /delete /tn "TG Digest" /f` (macOS: `launchctl unload ~/Library/LaunchAgents/kz.aitu.rubezh.digest.plist`).

## Чем суммаризировать

Инструмент **не привязан к одной модели**. Кончилась подписка — меняешь одну строчку.
Всё это живёт в [llm.py](llm.py), туда же смотрит проект-планировщик в соседней папке.

| `backend` | Кому подходит | Цена |
|---|---|---|
| `auto` (по умолчанию) | всем | берёт первое рабочее из списка ниже |
| `claude-cli` | есть подписка Claude Code | входит в подписку, лимитов бесплатного тира нет |
| `gemini-api` | **подписки нет** | бесплатный ключ с AI Studio, без карты |
| `ollama` | нужен офлайн или без лимитов | бесплатно, локально |
| `gemini-cli` | ⚠️ см. ниже | бесплатный тир для физлиц закрыт |

Посмотреть, что доступно прямо сейчас, и прогнать тестовый вызов:

```
python llm.py --check
```

**`auto` не просто выбирает — он подстраховывает.** Провайдер может быть установлен и всё
равно упасть на вызове: закрыли тир, кончилась квота, пропал интернет. В режиме `auto`
инструмент ловит это и переходит к следующему, а не падает. Проверено.

**Если у тебя нет подписки** — бери `gemini-api`: ключ на
[aistudio.google.com/apikey](https://aistudio.google.com/apikey) даётся бесплатно и без
карты, положи его в `.env` как `GEMINI_API_KEY`. Либо `ollama`, если хочешь совсем без
облака.

### Какую локальную модель брать

Проверено на 279 реальных сообщениях студенческого чата (RTX 5050 Laptop, 8 ГБ видеопамяти):

| Модель | Время | Нашла срочный дедлайн | Выдуманных номеров |
|---|---|---|---|
| **`gemma4:e4b`** | **65 с** | **да, с баллами и сроками** | **0** |
| `qwen3:8b` | 151 с | да, но без деталей | 0 |
| `qwen2.5:7b-instruct` | 178 с | нет | 15 |

Бери `gemma4:e4b`. `qwen3:8b` аккуратен, но вдвое медленнее и сжимает слишком сильно —
пишет «перезачёт по английскому», теряя проходные баллы, ради которых пункт и нужен.
`qwen2.5:7b` на коротких примерах выглядит прилично, а на реальной пачке разваливается:
вываливает сотни номеров подряд и теряет главное.

**Про `ollama_num_ctx` — самая коварная ловушка здесь.** По умолчанию Ollama берёт около
4k токенов и **молча обрезает** остальное. Модель не увидит большую часть чата и честно
ответит «ничего важного», а выглядеть это будет как исправно работающая программа.
16384 хватает на пачку из ~500 сообщений.

**⚠️ Про `gemini-cli`:** вход обычным гугл-аккаунтом там работает, но с августа 2026 Google
закрыл для личных аккаунтов бесплатный тир Gemini Code Assist и уводит в Antigravity.
Вызов возвращает `IneligibleTierError: UNSUPPORTED_CLIENT`. Провайдер оставлен в коде на
случай, если у тебя платный Code Assist или тир снова откроют, но по умолчанию не полагайся
на него. Проверено 2026-08-30 на свежей установке 0.57.0.

**Про приватность:** бесплатные тиры используют присланное для улучшения моделей, вплоть до
просмотра людьми. Для универских объявлений это обычно неважно. Если для тебя важно —
`ollama`, тогда текст вообще не покидает компьютер.

## Настройки в `config.json`

| Поле | Что делает |
|---|---|
| `chats` | Какие группы читать |
| `backend` | `auto`, `claude-cli`, `gemini-cli`, `ollama`, `gemini-api`, `fake` |
| `claude_model` | Модель для `claude-cli`, по умолчанию `sonnet` |
| `gemini_cli_model` | Модель для `gemini-cli` |
| `ollama_model` | Модель для `ollama`, рекомендуется `gemma4:e4b` |
| `ollama_num_ctx` | Размер контекста для `ollama`, по умолчанию 16384 — **не занижай** |
| `gemini_model` | Модель для `gemini-api` |
| `max_messages_per_chat` | Потолок сообщений за один запуск (защита от 10к сообщений) |
| `max_chars_per_message` | Длинные сообщения обрезаются до стольких символов |
| `max_requests_per_run` | Жёсткий потолок вызовов модели за прогон — страховка от слива квоты |

Что считать важным, а что флудом — задаётся текстом в переменной `PROMPT` в
[digest.py](digest.py). Правь под свои предметы: добавь названия курсов, имя старосты,
свои слова-маркеры.

## Про безопасность

`profiles/*/telegram.session` — это полный доступ к Telegram-аккаунту, не к одним лишь
сообщениям. Файл не коммить и никому не отправлять. Если он утечёт, отзови сессию:
Telegram → Настройки → Устройства → завершить сеанс.

**Если на машине несколько профилей, это чужие аккаунты.** Ставить чужой профиль можно
только с ведома владельца: вход он делает сам, своим кодом, и должен понимать, что файл
сессии остаётся на этом компьютере. Отозвать доступ он может в любой момент там же —
Настройки → Устройства. Вся папка `profiles/` в `.gitignore`.

Тексты сообщений уходят в Google Gemini API. Медиа (фото, файлы) не скачиваются и не
отправляются — только пометка, что вложение было.
